# 12. 게임이 돌아가는 원리

이 문서는 Token Sports의 **속**을 설명한다. 게임을 어떻게 하는지가 아니라, 경기 한 판이 컴퓨터 안에서 어떻게 만들어지는지, 훈련한 능력치가 어디에 쓰이는지, 평점은 어떻게 나오는지를 다룬다.

코드를 몰라도 읽을 수 있게 썼다. 수식이 나오면 바로 아래에 숫자를 넣은 예를 붙였다. 더 깊이 보고 싶은 사람을 위해 절마다 **어느 파일에 있는지**를 적었다.

숫자는 이 문서를 쓴 때의 코드에서 옮긴 것이다. 균형을 맞추면서 바뀔 수 있으니, 정확한 값이 필요하면 적어 둔 파일을 본다.

## 1. 한눈에 보기

게임 전체는 하나의 고리다.

```
코딩한다 (AI 도구가 토큰을 쓴다)
   │  앱이 20초마다 로그 파일을 읽는다
   ▼
훈련 포인트가 쌓인다 (토큰 1개 = 1포인트)
   │  훈련 탭에서 포인트를 쓴다
   ▼
능력치가 오른다 (예: 슈팅 41.2 → 41.9)
   │  한 시간에 한 번 경기 기회가 생긴다
   ▼
경기를 치른다 ── 능력치가 "확률"이 되어 주사위를 굴린다
   │
   ▼
기록이 남는다 (3타수 2안타, 1골 1도움, 17분 13점)
   │  기록에 점수를 매긴다
   ▼
평점이 나온다 (6.0이 "무난했다")
   │
   ├─▶ 감독 신뢰가 오르내린다 ─▶ 선발이 되거나 벤치로 간다
   ├─▶ 명성이 오른다 ─────────▶ 스카우트가 지켜보기 시작한다
   ├─▶ 스카우트의 관심이 쌓인다 ▶ 윗 리그 구단에서 제안이 온다
   └─▶ 경기를 뛴 만큼 능력이 조금 저절로 오른다
```

이 문서의 나머지는 이 고리의 화살표 하나하나를 풀어 쓴 것이다.

## 2. 먼저 알아 둘 세 가지 원리

세 종목의 경기 엔진은 모양이 다 다르지만, 밑바닥의 원리 세 가지는 같다. 이것만 알면 나머지는 응용이다.

### 원리 1: 모든 일은 "확률 + 주사위"다

경기에서 일어나는 일은 전부 이런 식으로 정해진다.

1. 상황과 능력치로 **확률**을 계산한다. (예: "이 슛이 들어갈 확률 46%")
2. 0과 1 사이의 수를 하나 뽑는다. **주사위**다.
3. 뽑은 수가 확률보다 작으면 일어난다. (0.31이 나왔으면 0.46보다 작으니 들어간다)

코드에서는 `rng.chance(0.46)` 한 줄이다. 경기 엔진 전체가 이 한 줄의 반복이다.

여러 결과 가운데 하나를 고를 때는 **가중치 주사위**를 쓴다. 누가 슛을 던질지 고를 때, 슛 능력이 80인 선수는 40인 선수보다 두 배쯤 자주 뽑힌다. 코드에서는 `rng.weighted([80, 40, 55, …])`이다.

> 그래서 능력치가 높다고 반드시 이기지 않는다. 확률이 높아질 뿐이다. 한 경기는 운이 크고, 한 시즌은 실력이 드러난다.

### 원리 2: 능력치는 "차이"로 작동한다

확률은 대부분 **내 능력 − 상대 능력**으로 계산한다. 절대값이 아니다.

- 타자의 컨택이 60이고 투수의 구위가 60이면 차이는 0이다. 기본 확률 그대로다.
- 컨택이 70이고 구위가 60이면 차이는 +10이다. 맞힐 확률이 4%p 오른다 (차이 1마다 0.4%p).

왜 이렇게 하는가. 리그가 올라가면 **모두** 강해진다. 절대값으로 계산하면 1부 리그는 타자가 다 잘 쳐서 매 경기 20점이 나고, 6부 리그는 아무도 못 쳐서 0 대 0이 된다. 차이로 계산하면 1부도 6부도 점수가 비슷하게 나고, 그 안에서 더 강한 쪽이 유리해진다.

> 이것이 "리그가 올라가면 다시 어려워지는" 이유다. 6부에서 능력 40이면 스타지만, 5부에 가면 상대도 40이라 차이가 0으로 돌아간다.

농구만 예외를 조금 뒀다. 능력의 절대값도 성공률에 조금 반영해서, 6부 경기는 60점대, 1부 경기는 80점대가 나온다. 아마추어 농구가 프로보다 점수가 덜 나는 것을 흉내 냈다.

### 원리 3: 같은 시드면 같은 경기가 나온다

주사위는 진짜 무작위가 아니다. **시드**라는 숫자 하나에서 출발해 정해진 순서로 수를 만들어 낸다 (SplitMix64라는 방식). 시드가 같으면 뽑히는 수의 순서가 완전히 같다.

- 경기를 시작할 때 시드를 하나 정해 경기 안에 넣어 둔다.
- 경기 상태를 저장할 때 주사위의 현재 위치까지 같이 저장한다.

그래서 **경기 도중에 앱을 껐다 켜도 똑같이 이어진다.** 다시 켰을 때 다른 결과가 나오게 하려고 껐다 켜는 꼼수가 통하지 않는다. 또 테스트에서 "이 시드로 한 시즌을 돌리면 이 결과가 나와야 한다"를 검사할 수 있다.

📁 `Sources/TokenBaseballCore/Support/SeededRNG.swift` (80줄. 가장 먼저 읽기 좋은 파일이다.)

## 3. 선수는 숫자 몇 개로 이루어져 있다

선수 한 명은 이런 값들의 묶음이다.

| 값 | 뜻 | 예 |
|---|---|---|
| 이름, 나이, 포지션 | | 김하늘, 16세, 공격수 |
| **세부 능력치** | 1~99. 종목마다 쓰는 것이 다르다 | 슈팅 41.2, 드리블 33.0, … |
| **능력** (CA) | 세부 능력치를 포지션의 비중으로 평균 낸 값. 화면의 "능력 22" | 22.4 |
| **잠재력** (PA) | 능력이 오를 수 있는 한계. 숨겨져 있다 | 79 |
| 시즌 기록 | 이번 시즌에 쌓은 기록 | 12경기 3골 2도움 |
| 계약, 특성, 컨디션 | | 연봉, "강철 체력" 등 |

### 능력(CA)은 어떻게 계산하는가

포지션마다 **어떤 능력치가 얼마나 중요한지**가 정해져 있다. 축구 공격수는 이렇다.

| 슈팅 | 드리블 | 스피드 | 피지컬 | 패스 | 체력 |
|---|---|---|---|---|---|
| 38% | 20% | 17% | 10% | 8% | 7% |

능력은 이 비중으로 낸 평균이다.

```
능력 = 슈팅×0.38 + 드리블×0.20 + 스피드×0.17 + 피지컬×0.10 + 패스×0.08 + 체력×0.07
```

예: 슈팅 50, 드리블 40, 스피드 40, 피지컬 30, 패스 30, 체력 30인 공격수.

```
50×0.38 + 40×0.20 + 40×0.17 + 30×0.10 + 30×0.08 + 30×0.07
= 19 + 8 + 6.8 + 3 + 2.4 + 2.1 = 41.3
```

여기서 중요한 점 두 가지.

- **능력은 요약 숫자일 뿐, 경기에서 직접 쓰이지 않는다.** 경기 엔진은 세부 능력치(슈팅, 패스…)를 본다. 능력은 감독이 선발을 정할 때, 팀 강도를 계산할 때, 연봉을 정할 때 쓴다.
- **비중에 없는 능력치도 경기에서는 쓰인다.** 공격수의 수비 능력치는 능력 계산에 안 들어가지만, 공을 뺏는 장면에서는 쓰인다. 다만 훈련으로 올릴 수는 없다.

📁 `Sources/TokenBaseballCore/Players/Player.swift`의 `Attributes.weights(for:)`

### 선수는 어떻게 만들어지는가

새 선수를 만들 때는 "목표 능력"을 먼저 정하고, 거기에 맞는 세부 능력치를 뽑는다.

1. 포지션에 중요한 능력치마다 `목표 능력 + 무작위(표준편차 6)`를 뽑는다. 그래서 같은 능력 40이어도 슈팅이 좋은 선수, 스피드가 좋은 선수가 나온다.
2. 중요하지 않은 능력치는 목표의 일부만 준다 (야수는 25%, 축구·농구는 60% 안팎).
3. 비중으로 평균을 내 보고 목표와 어긋나면 전체를 조금 밀어 맞춘다.

내 선수는 여기에 **타고난 재능**이 붙는다. 능력 15~30, 잠재력 68~95 사이에서 무작위로 정해지고, 시작 포인트 5개를 직접 나눠 넣는다.

📁 `Sources/TokenBaseballCore/Players/PlayerFactory.swift`

## 4. 경기는 "틱"으로 흘러간다

경기 엔진은 스스로 시간을 흘려보내지 않는다. 바깥에서 **"한 걸음 가라"**(`step()`)고 부를 때마다 한 걸음씩 간다. 이 한 걸음을 틱이라고 부른다.

| 종목 | 한 틱 | 한 경기의 틱 수 |
|---|---|---|
| 야구 | 공 하나 (또는 도루·폭투 하나) | 양 팀의 투구 수만큼 (경기마다 다르다) |
| 축구 | 경기 시간 20초 | 270개 + 추가시간 |
| 농구 | 경기 시간 8초 | 300개 |

앱은 **3초에 한 번** 틱을 부른다. 그래서 세 종목 모두 한 경기가 15분쯤 걸린다. 틱의 크기를 종목마다 다르게 잡은 것은 이 15분을 맞추기 위해서다.

```
앱 (3초마다)                    경기 엔진
   │   step() ──────────────▶  확률 계산, 주사위, 상태 변경
   │   ◀── [일어난 일 목록] ──   "3구째 직구 142km, 바깥쪽 … 헛스윙!"
   │
   ├─ 중계 화면에 한 줄 추가
   ├─ 득점이면 알림
   └─ 장면에 따라 조금 더 쉰다 (이닝 교대 +4초, 교체 +3초, 득점 +2초)
```

- **배속**(2×, 4×, 8×)은 기다리는 3초를 줄일 뿐이다. 경기 내용은 배속과 상관없이 같다.
- **결과 바로 보기**는 토큰 100만을 내고 남은 틱을 기다리지 않고 한 번에 돌린다 (`skipMatchToEnd` → `runMatchToEnd`). 주사위는 경기를 시작할 때 정해진 시드에서 나오므로, 결과는 끝까지 지켜봤을 때와 같다.
- 다른 구장의 경기(같은 라운드의 다른 팀들)도 같은 엔진으로 같이 한 틱씩 간다. 그래서 "타 구장 소식"의 점수가 실시간으로 변한다.
- 화면에 안 보이는 경기(다른 다섯 리그, 컵대회의 남의 경기)는 `runToEnd()`로 한 번에 끝까지 돌린다. 같은 엔진이고, 기다리지 않을 뿐이다.

틱이 돌려주는 "일어난 일"에는 종류가 붙어 있다: 투구(`pitch`), 플레이(`play`), 득점(`score`), 이닝·쿼터 경계(`inning`), 교체(`change`), 주루(`running`), 종료(`end`). 앱은 이 종류를 보고 얼마나 쉴지, 알림을 보낼지를 정한다.

📁 앱 쪽 반복문: `Sources/TokenBaseball/Model/AppModel+Match.swift`의 `runMatchLoop`
📁 엔진을 부르는 쪽: `Sources/TokenBaseballCore/Game/Game+Match.swift`의 `stepMatch`

## 5. 야구 경기의 속

야구는 세 종목 가운데 가장 잘게 쪼갠다. **공 하나가 한 틱**이다.

### 5.1 경기가 기억하는 것

경기 상태는 이것이 전부다.

- 몇 회 초·말인지, 아웃 카운트, 볼, 스트라이크
- 1루·2루·3루에 누가 있는지 (주자마다 "어느 투수가 내보냈는지", "실책으로 나갔는지"를 달고 있다. 자책점 계산용이다)
- 양 팀의 타순 9명과 투수들, 각자의 이 경기 기록
- 주사위의 현재 위치

### 5.2 공 하나가 정해지는 순서

타석에 타자가 서면, 공 하나는 아래 순서로 정해진다. 중간에 결과가 나오면 거기서 끝난다.

```
① 투수가 지쳤는가        → 구위와 제구를 깎는다
② 상황 보정              → 득점권, 특성, 홈 이점
③ 구종을 고른다          → 직구 / 슬라이더 / 커브 / 체인지업 / 포크
④ 존을 노리는가          → 볼카운트에 따라
⑤ 노린 대로 들어가는가    → 제구
⑥ 타자가 휘두르는가      → 존 안이면 대체로, 존 밖이면 선구안에 따라
     └ 안 휘두름 → 스트라이크 또는 볼 (끝)
⑦ 맞는가                → 컨택 − 구위
     └ 안 맞음 → 헛스윙 (끝)
⑧ 파울인가              → 42~50%
     └ 파울 (끝)
⑨ 인플레이! → 5.3으로
```

단계별 숫자는 이렇다.

**① 지침.** 투수마다 "한도 투구 수"가 있다. 선발은 `35 + 체력×0.8`, 불펜은 `22 + 체력×0.45`. 체력 60인 선발이면 83구다. 한도를 넘긴 공 하나마다 구위가 0.35, 제구가 0.45씩 떨어진다. 100구째면 17개를 넘겼으니 구위 −6, 제구 −7.7이다.

**② 상황 보정.**
- 2루나 3루에 주자가 있을 때: "위기에 강함" 투수는 구위·제구 +4, "찬스에 강함" 타자는 컨택 +5·파워 +3.
- 홈 이점: 구장 레벨에 따라 0.5~2.5 정도를 홈 팀 타자의 컨택(공격할 때)이나 홈 팀 투수의 구위(수비할 때)에 더한다.

**③ 구종.** 직구 비율은 `0.65 − 변화구×0.003` (최소 30%). 변화구 능력이 50이면 직구 50%, 나머지를 슬라이더 40%, 커브 24%, 체인지업 24%, 포크 12%로 나눈다. 구속은 `108 + 구위×0.48 − 구종별 감속`으로 중계에 찍힌다 (구위 70인 직구는 142km쯤).

**④ 존을 노리는가.** 기본 45%에, 볼이 스트라이크보다 많을수록 더 노린다 (차이 하나에 +7%p). 3볼이면 +12%p, 2스트라이크에 볼이 적으면 −12%p (유인구를 던진다).

**⑤ 들어가는가.** 존을 노렸을 때 실제로 존에 들어갈 확률은 `0.66 + 제구×0.003`. 제구 60이면 84%다. 안 노렸는데 존에 들어가는 실투는 10% 안팎이다.

**⑥ 스윙.**
- 존 안: 64%가 휘두른다. 2스트라이크면 88%.
- 존 밖: `0.30 − (선구안−50)×0.003`. 선구안 70이면 24%, 선구안 30이면 36%가 속는다. 변화구면 조금 더 속고, 2스트라이크면 10%p 더 속는다.

**⑦ 맞는가.** 존 안의 공은 `0.84 + (컨택−구위)×0.004`, 존 밖의 공은 `0.60 + …`. 컨택 60 대 구위 70이면 존 안 공을 80%로 맞힌다. 변화구는 3%p쯤 덜 맞는다.

**⑧ 파울.** 맞은 공의 42%(존 안)~50%(존 밖)는 파울이다. 2스트라이크에서는 카운트가 늘지 않는다.

### 5.3 맞은 공은 어디로 가는가

인플레이가 되면 다시 순서대로 판정한다.

**홈런인가.** 확률은 대략 3.2%에서 시작해 `파워 − 구위`에 따라 지수로 변한다.

```
홈런 확률 = 0.032 × e^((파워−구위)/40) × (0.8 + 파워/250) × (제구가 좋으면 조금 감소)
```

파워 70 대 구위 60이면 4.4%쯤, 파워 50 대 구위 70이면 1.9%쯤이다. 차이는 −30에서 +60까지만 인정하고, 확률은 0.2%~16% 밖으로 나가지 않는다. 파워 90인 타자가 구위 25인 투수를 만나면 16%다.

**타구의 종류.** 땅볼 44%, 뜬공 33%, 라이너 23%. 종류에 따라 어느 수비수에게 가는지를 뽑는다 (땅볼은 내야수, 뜬공은 외야수).

**안타인가.** 타구 종류마다 기본 확률이 크게 다르다.

| 타구 | 기본 안타 확률 | 견주는 것 |
|---|---|---|
| 라이너 | 67% | 수비수의 수비 대 타자의 컨택 |
| 땅볼 | 24.5% | 수비수의 수비 대 타자의 **주력** |
| 뜬공 | 14% | 수비수의 수비 대 타자의 **파워** |

여기에 `컨택 − 구위`가 조금 더해진다. 땅볼을 치고 발로 사는 타자, 뜬공을 멀리 보내는 타자가 이렇게 갈린다.

**몇 루타인가.** 땅볼 안타는 단타다. 라이너는 단타 74% · 2루타 23% · 3루타 3% (파워가 높으면 2루타가 는다). 뜬공 안타는 단타 40% · 2루타 50% · 3루타 10%.

**안타가 아니면.** 실책(수비가 낮을수록, 0.5~9%)을 한 번 더 보고, 아니면 아웃이다. 아웃도 그냥 아웃이 아니다.

- 땅볼 아웃: 1루에 주자가 있고 2아웃 전이면 **병살**이 될 수 있다 (42%에서 타자 주력과 수비력으로 가감). 아니면 주자들이 한 베이스씩 갈 수 있다.
- 뜬공 아웃: 3루 주자가 있으면 **희생플라이**를 본다 (50%에서 주자의 발 대 외야수의 어깨).
- 라이너 아웃: 직선타. 주자는 못 움직인다.

### 5.4 주자와 투수 교체

- **주루**: 단타에 2루 주자가 홈까지 들어올 확률은 기본 60%이고 `주자의 주력 − 외야수의 어깨`로 가감한다.
- **도루**: 공을 던지기 전에 본다. 1루 주자가 뛸 확률은 공 하나마다 1.2%쯤이고, 성공률은 `0.62 + (주력 − 포수 어깨)×0.006`. 도루가 일어난 틱에는 공을 던지지 않는다.
- **폭투**: 공 하나마다 0.3%에 제구가 60보다 낮으면 조금 더.
- **투수 교체**: 타석이 바뀔 때마다 감독(CPU)이 본다. 선발은 투구 수 한도나 실점 한도(기본 5점)를 넘기면 내려간다. 9회에 1~3점 앞서 있고 주자가 없으면 마무리가 올라온다.

### 5.5 예: 타석 하나

컨택 62 · 파워 55 · 선구안 48인 타자와 구위 58 · 제구 52 · 변화구 45인 투수.

| 공 | 일어난 일 | 판정 |
|---|---|---|
| 1구 | 존을 노림(45%) → 들어감(82%) → 타자가 안 휘두름(36%) | 스트라이크 |
| 2구 | 존을 안 노림(0-1에서 38%만 노림) → 빠짐 → 타자가 안 속음(69%) | 볼 |
| 3구 | 존을 노림 → 들어감 → 휘두름(64%) → 맞음(86%) → 파울(42%) | 파울, 1-2 |
| 4구 | 유인구 → 빠짐 → 2스트라이크라 속을 확률 41% → 속음 → 맞음(62%) → 인플레이 | |
| | 홈런 아님(3%) → 땅볼(44%) → 유격수 쪽 → 안타 확률 24% → 아웃 | 유격수 땅볼 아웃 |

중계에는 "4구째 슬라이더 131km, 바깥쪽 빠지는 유격수 땅볼 아웃"이 나온다.

## 6. 축구 경기의 속

축구는 공 하나하나를 그리지 않는다. **20초를 한 덩어리**로 보고, 그 20초 동안 공이 어디로 갔는지만 정한다.

### 6.1 경기장은 세 구역이다

```
   [ 우리 진영 ]      [ 중원 ]      [ 상대 진영 ]
      구역 0           구역 1          구역 2
```

경기는 "공이 어느 구역에 있고, 누가 갖고 있는가" 두 가지만 기억한다. 구역 번호는 **공을 가진 팀 기준**이다. 공을 뺏기면 상대 기준으로 뒤집힌다 (내 구역 2에서 뺏기면 상대의 구역 0이다).

### 6.2 틱마다 일어나는 일

틱마다 지금 구역에 맞는 **두 능력을 견주어** 배율 하나를 만든다.

```
배율 m = e^((공격 쪽 값 − 수비 쪽 값) / 90)      (0.4배 ~ 2.5배 사이)
```

- 두 값이 같으면 m = 1 (기본 확률 그대로).
- 공격 쪽이 10 높으면 m = 1.12. 20 높으면 1.25.
- 수비 쪽이 10 높으면 m = 0.89.

그리고 구역마다 정해진 표로 주사위를 굴린다.

| 구역 | 공격 쪽 값 | 수비 쪽 값 | 전진 | 뺏김 | 나머지 |
|---|---|---|---|---|---|
| 0 우리 진영 | 수비수·미드필더의 패스 | 상대 공격수·미드필더의 수비+스피드 | 58% × m | 8% ÷ m | 뒤에서 공을 돌린다 |
| 1 중원 | 미드필더의 패스(60%)+드리블(40%) | 상대 미드필더의 수비(70%)+피지컬(30%) | 34% × m | 27% ÷ m | 기회를 엿본다 |
| 2 상대 진영 | 공격수·미드필더의 드리블+스피드+패스 | 상대 수비수의 수비+피지컬+스피드 | 아래 표 | | |

"전진"하면 공이 다음 구역으로 간다. "뺏김"이면 공격권이 넘어간다 (중원에서 뺏길 때 42%는 반칙으로 끝나 공을 그대로 갖는다).

상대 진영(구역 2)에서는 결과가 여러 가지다.

| 결과 | 확률 |
|---|---|
| **슈팅** | 21% × m |
| 페널티킥을 얻는 반칙 | 0.3% × m |
| 오프사이드 | 3.5% |
| 공을 잃음 | 33% ÷ m (그중 22%는 위험한 위치의 프리킥, 22%는 코너킥, 나머지는 뺏김. 뺏긴 것의 20%는 역습) |
| 기회를 엿본다 | 나머지 |

여기에 네 가지가 더 얹힌다.

- **포메이션**: 구역마다 값을 더하거나 뺀다. 4-3-3은 상대 진영에서 +3, 중원에서 −2. 5-3-2는 수비에서 +4, 중원에서 −2.
- **전술**: 공격적이면 공격 쪽 값 +4, 수비 쪽 값 −4.
- **홈 이점**: 홈 팀의 값에 2~4를 더한다. 중립 구장(플레이오프 결승)에서는 0이다.
- **퇴장**: 한 명이 빠질 때마다 8을 뺀다.

### 6.3 슈팅 하나가 골이 되기까지

슈팅이 나오면 네 단계를 거친다.

```
① 누가 차는가      공격수 3 · 미드필더 1.4 · 수비수 0.35의 비율에 "슈팅 몫"을 곱한 가중치로 뽑는다
                  슈팅 몫 = ((슈팅 + 20) / 70)^1.5   (슈팅 25 → 0.52, 60 → 1.22, 90 → 1.97)
② 수비에 막히는가   0.24 × e^((수비수들의 수비 − 슈팅)/100)     → 막히면 코너킥이나 공격권 상실
③ 골문으로 가는가   0.41 + (슈팅 − 골키핑)/300                  → 빗나가면 공격권 상실
④ 들어가는가       0.36 × e^((슈팅 − 골키핑)/90)               → 아니면 선방
```

예: 슈팅 60인 공격수, 상대 수비수 평균 수비 55, 골키퍼 골키핑 58.

- ② 막힐 확률: 0.24 × e^(−0.05) = 22.8%
- ③ 유효 슈팅: 0.41 + 2/300 = 41.7%
- ④ 골: 0.36 × e^(2/90) = 36.8%

슈팅 하나가 골이 될 확률은 `0.772 × 0.417 × 0.368 = 11.8%`. 슈팅 여덟아홉 개에 한 골꼴이다. 이 세 확률은 한 경기에 두 팀 합쳐 2.8골쯤(실제 축구와 비슷한 수) 나오도록 맞춘 것이고, 테스트가 이 범위를 지킨다.

골이 들어가면 70%의 확률로 도움이 붙는다 (미드필더 2 · 공격수 1.5 · 수비수 0.8의 비율에 패스로 계산한 같은 몫을 곱해 뽑는다).

"몫"이 능력에 가파르게 반응하는 것이 중요하다. 슈팅 90인 공격수는 슈팅 25인 동료보다 3.8배 자주 슛을 맡는다. 팀이 만드는 슈팅 수는 그대로이고, 그 안에서 잘하는 선수에게 공이 몰린다. 비슷한 선수끼리는 몫이 거의 같다.

**세트피스**는 다음 틱에 따로 처리한다.
- 코너킥: 16%가 헤딩슛으로 이어진다.
- 위험한 위치의 프리킥: 35%는 직접 슈팅(유효 36%, 그중 골 20% 안팎).
- 페널티킥: `0.76 + (슈팅 − 골키핑)/250` (55~92%).

### 6.4 체력, 카드, 교체

- **체력**: 선수마다 1에서 시작해 틱마다 `0.0019 × (1.25 − 체력/100×0.7)`씩 준다. 체력 50이면 90분 뒤 0.54쯤 남는다. 능력치는 `0.75 + 0.25×남은 체력`을 곱해서 쓰이므로, 다 지친 선수는 능력의 80%쯤만 낸다.
- **반칙과 카드**: 반칙의 13%(위험한 반칙은 24%)에 경고가 나온다. 경고 두 장이면 퇴장이다. 곧바로 퇴장은 0.1%, 페널티킥을 준 반칙이면 2%.
- **교체**: 60분부터 감독이 지친 선수를 같은 포지션의 벤치 선수로 바꾼다. 최대 다섯 명.
- **끝**: 90분에 추가시간(1~5분)을 더한다. 승부가 나야 하는 경기(컵대회, 플레이오프)는 연장 30분, 그래도 같으면 승부차기를 한 틱에 한 명씩 찬다.

## 7. 농구 경기의 속

농구는 **공격권**(한 팀이 공을 잡고 슛을 던지거나 잃을 때까지)이 단위다. 한 틱은 8초이고, 공격 한 번은 1~3틱(8~24초)이 걸린다.

### 7.1 공격 한 번의 순서

공격이 끝나는 틱에 아래 순서로 판정한다.

```
① 실책인가            → 그렇다면 공격권이 넘어간다 (55%는 상대의 스틸로 기록)
② 누가 던지는가       → 슛 능력 × 포지션 × 플레이 스타일의 가중치
③ 3점슛인가           → 선수의 3점슛 능력과 포지션
④ 슛 반칙인가         → 그렇다면 자유투 2개 (3점슛이었으면 3개)
⑤ 들어가는가
     ├ 들어감 → 득점. 어시스트를 본다. 공격권이 넘어간다
     └ 빗나감 → 블록인지 본다 → ⑥ 리바운드
⑥ 리바운드
     ├ 공격 리바운드 → 다음 틱에 골밑 슛 기회 (실책 없이, 성공률 +6%p)
     └ 수비 리바운드 → 공격권이 넘어간다
```

**① 실책.** `0.20 − 볼 다루기×0.0011 + (상대 압박 − 볼 다루기)×0.0025` (6~26%).
볼 다루기는 코트 위 다섯 명의 `드리블×0.6 + 패스×0.4` 평균이고, 압박은 상대 다섯 명의 `수비×0.6 + 스피드×0.4` 평균이다. 능력 60끼리면 13%쯤이다.

**② 슈터.** 가중치는 `(슛×0.6 + 3점슛×0.4) × 포지션 계수`. 포지션 계수는 슈팅 가드 1.25, 스몰 포워드 1.15, 포인트 가드 0.95, 파워 포워드 0.9, 센터 0.8. 슈팅 가드가 가장 많이 던진다.

**③ 3점인가.** `0.24 + 포지션 보정 + (3점슛 − 슛)×0.005`. 보정은 슈팅 가드 +0.16, 포인트 가드 +0.10, 스몰 포워드 +0.04, 파워 포워드 −0.08, 센터 −0.16. 3점슛이 슛보다 좋은 선수일수록 밖에서 던진다.

**④ 슛 반칙.** 2점슛의 13%, 3점슛의 3%. 자유투 성공률은 `0.5 + 슛×0.004` (슛 60이면 74%). 다섯 번째 반칙이면 그 선수는 물러난다.

**⑤ 성공률.** 맞은편 수비수(같은 자리에 선 상대)의 수비 60%와 상대 팀 평균 수비 40%를 섞은 값을 "저항"으로 쓴다.

```
2점슛 = 0.36  + 실력×0.0026 + (실력 − 저항)×0.004     (실력 = 슛×0.8 + 피지컬×0.2)
3점슛 = 0.215 + 실력×0.002  + (실력 − 저항)×0.0035    (실력 = 3점슛)
```

능력 60끼리면 2점슛 51.6%, 3점슛 33.5%다. 여기서 **절대값 항**(`실력×0.0026`)이 원리 2의 예외다. 능력 25끼리면 2점슛 42.5%, 능력 85끼리면 58%가 되어 리그 수준에 따라 득점이 달라진다.

**⑥ 리바운드.** 선수마다 `(리바운드×0.7 + 피지컬×0.3) × 포지션 계수`를 계산해 팀별로 더한다. 포지션 계수는 센터 2.6, 파워 포워드 2.2, 스몰 포워드 1.2, 가드 0.7. 공격 리바운드 확률은 `0.27 × (공격 쪽 합 ÷ 수비 쪽 합)` (14~42%).

### 7.2 체력과 교체

농구는 교체가 자유로워서 체력이 경기의 흐름을 만든다.

- 코트 위에서는 틱마다 체력이 줄고, 벤치에서는 틱마다 0.006씩 회복한다. 쿼터 사이에 0.1, 하프타임에 0.2를 더 회복한다.
- 공격권이 바뀔 때마다 감독이 본다: 체력이 0.55 아래로 떨어진 선수를 체력이 0.8 넘게 남은 같은 포지션의 벤치 선수로 바꾼다.
- 4쿼터 마지막 3분과 연장에는 벤치에 있던 **주전을 다시 올린다.**

이 규칙만으로 주전은 28분쯤, 벤치는 8~13분쯤 뛰게 된다. 따로 "출전 시간표"를 정해 두지 않았는데도 그렇게 나온다.

### 7.3 끝

10분 4쿼터를 마쳤을 때 동점이면 5분 연장을 승부가 날 때까지 한다. 무승부가 없다.

## 8. 내 선수는 경기에 어떻게 끼어드는가

가장 중요한 사실: **경기 엔진은 내 선수를 모른다.** 엔진이 보기에 내 선수는 22명(축구) 가운데 한 명일 뿐이다. 내 선수만 잘되게 하는 숨은 보정은 없다.

내 선수가 특별해지는 것은 **경기 앞**과 **경기 뒤**뿐이다.

### 8.1 경기 앞: 출전

감독(CPU)이 내 선수를 어떻게 쓸지 정한다.

```
선발 조건:  내 능력 + (감독 신뢰 − 50)/10  ≥  같은 포지션 경쟁자의 능력
```

감독 신뢰가 50이면 보정이 0이다. 신뢰 80이면 +3, 신뢰 20이면 −3이다. 능력이 조금 모자라도 신뢰가 높으면 선발이 되고, 능력이 조금 앞서도 신뢰가 낮으면 벤치다.

| 종목 | 선발이 아닐 때 |
|---|---|
| 야구 타자 | 항상 선발이다. 감독 신뢰는 타순을 바꾼다 (높으면 앞 타순) |
| 야구 선발 투수 | 쉬는 날을 채우면 반드시 선발로 나온다. 신뢰가 높으면 더 오래 던지게 둔다 |
| 야구 불펜 | 선발이 내려가면 가장 먼저 올라온다 |
| 축구 | 벤치에서 시작해 정해진 시간에 반드시 교체로 들어간다 (신뢰 40이면 70분, 80이면 50분) |
| 농구 | 벤치에서 시작해 정해진 시간만큼 반드시 뛴다 (신뢰 40이면 15분, 90이면 24분) |

"반드시 나온다"는 현실적이지 않지만, 15분을 지켜봤는데 내 선수가 한 번도 안 나오면 재미가 없어서 그렇게 했다.

### 8.2 경기 앞: 능력치에 곱해지는 것

경기를 시작할 때 내 선수의 능력치를 엔진에 넘기면서 두 가지를 곱한다.

- **컨디션**: 경기마다 다시 뽑는다. 최상 +6%(10%), 좋음 +3%(25%), 보통(40%), 나쁨 −3%(20%), 최악 −6%(5%).
- **기세**: 평점 7.0 이상이 세 경기 이어지면 +2%, 5.5 이하가 세 경기 이어지면 −2%.

슈팅 50인 선수가 컨디션 최상에 기세가 붙으면 그 경기에서는 슈팅 54로 뛴다. 선수의 실제 능력치는 바뀌지 않는다.

### 8.3 경기 앞: 플레이 스타일 (축구, 농구)

스타일은 **가중치 주사위의 내 몫**을 바꾼다. "욕심내기"는 슈터를 뽑을 때 내 가중치를 1.7배로 만든다. 다섯 명 가운데 내가 뽑힐 확률이 20%였다면 30%쯤으로 오른다. 대신 도움을 줄 선수로 뽑힐 가중치는 0.55배가 된다.

능력치를 올려 주는 것이 아니다. **무엇을 더 자주 할지**를 고르는 것이다.

### 8.4 그러면 훈련은 어디에 나타나는가

능력치가 오르면 두 군데에서 효과가 난다.

1. **내가 뽑히는 횟수.** 슈터를 뽑는 가중치에 슈팅 능력이 들어 있다. 슈팅이 오르면 슛을 더 자주 던진다. 패스가 오르면 도움을 더 자주 올린다.
2. **뽑혔을 때의 성공률.** 슛이 들어갈 확률에 슈팅 능력이 들어 있다.

그래서 "슈팅을 올렸더니 골이 늘었다"는 두 효과가 곱해진 결과다. 한두 경기로는 운에 묻혀 안 보이고, 한 시즌 기록에서 보인다.

**능력 차이가 기록으로 나타나는 정도.** 6부(리그 평균 능력 28쯤)에 능력이 다른 선수를 넣고 한 시즌씩 두 번 돌린 평균이다. 모든 능력치를 그 수준으로 맞췄고 매 경기 선발로 나왔다.

| 내 능력 | 28 (리그 평균) | 48 | 62 | 76 | 90 |
|---|---|---|---|---|---|
| 축구 공격수: 경기당 골 (평점) | 0.23 (6.4) | 0.56 (7.4) | 1.11 (8.0) | 1.56 (8.5) | 2.41 (9.2) |
| 축구 미드필더: 경기당 골 (평점) | 0.07 (6.1) | 0.50 (7.3) | 0.73 (7.8) | 1.18 (8.4) | 1.43 (9.0) |
| 축구 골키퍼: 무실점 경기 (평점) | 4 (6.6) | 18 (7.1) | 22 (7.3) | 23.5 (7.3) | 24 (7.4) |
| 야구 유격수: 타율 · 홈런 (평점) | .280 · 3 (6.8) | .340 · 7 (7.2) | .390 · 9 (7.5) | .480 · 15.5 (8.1) | .530 · 20 (8.3) |
| 야구 선발 투수: 평균자책점 (평점) | 3.80 (6.9) | 2.38 (7.7) | 1.89 (8.6) | 0.76 (9.4) | 0.85 (9.5) |
| 농구 슈팅 가드: 평균 득점 (평점) | 8.5 (6.0) | 18.6 (6.7) | 35.8 (8.3) | 50.4 (8.8) | 61.1 (9.3) |

다시 재려면 `TB_LEVELS=28,48,62,76,90 TB_SEEDS=2 TB_PROBE=star swift test --filter CareerOfferProbe` (26분).

고치기 전에는 축구 공격수가 능력 48 → 62 → 76에서 경기당 0.63 → 0.58 → 0.87골로 거의 평평했고, 야구 타자의 홈런은 능력과 상관없이 7~11개였다. 골키퍼는 무실점 26경기를 해도 평점이 6.9였고, 농구는 평점이 10에 붙었다. 그래서 네 가지를 고쳤다: 축구에서 슛·도움·수비 장면을 맡는 몫이 능력에 더 가파르게 반응하게 했고, 야구 홈런이 파워와 구위의 차이를 60까지 인정하게 했고, 골키퍼의 무실점 평점을 올렸고, 농구 평점이 8.5 위로는 완만하게 오르게 했다.

## 9. 경기가 끝난 뒤에 일어나는 일

경기의 마지막 틱이 끝나면 한꺼번에 여러 일이 일어난다. 순서대로 적는다.

### 9.1 기록을 옮긴다

경기 안에서만 쓰던 기록(이 경기 3타수 2안타)을 선수의 시즌 기록에 더한다. 순위표에 승패와 득실을 적는다. 컵대회와 플레이오프는 순위표와 시즌 기록에 넣지 않는다.

### 9.2 같은 라운드의 나머지 경기를 끝낸다

내 리그의 다른 경기는 같이 돌고 있었으니 남은 부분만 끝까지 돌린다. **다른 다섯 리그**의 같은 라운드는 이때 한 번에 끝까지 돌린다. 내가 경기 하나를 치르면 온 세계가 한 라운드씩 나아간다.

### 9.3 평점을 매긴다

내 선수의 이 경기 기록에 점수를 매긴다. 6.0에서 시작해 한 일을 더하고 못한 일을 뺀다.

**야구 타자** (6.1에서 시작)

| | | | |
|---|---|---|---|
| 단타 | +0.55 | 삼진 | −0.2 |
| 2루타 | +0.8 | 그 밖의 아웃 | −0.15 |
| 3루타 | +1.0 | | |
| 홈런 | +1.4 | | |
| 타점 | +0.3 | | |
| 득점 | +0.2 | | |
| 볼넷 | +0.25 | | |
| 도루 | +0.3 | | |

예: 4타수 2안타(단타 1, 2루타 1) 1타점 1삼진 → `6.1 + 0.55 + 0.8 + 0.3 − 0.2 − 0.15 = 7.4`. 팀이 이겼으면 +0.2로 7.6이다.

**축구와 농구**는 뛴 시간이 짧으면 6.0 쪽으로 당기는 보정이 하나 더 있다.

```
평점 = 6.0 + (한 일 − 못한 일 + 팀 결과 + 포지션 보정) × 뛴 시간 보정
```

10분 뛰고 한 골 넣었다고 9.0이 나오지 않게 하는 장치다. 축구는 `0.35 + 뛴 시간/90 × 0.65`, 농구는 `0.35 + 뛴 시간/30 × 0.65`를 곱한다 (최대 1).

**포지션 보정**은 포지션마다 기록이 쌓이는 양이 달라서 넣었다. 공격수는 골이 쌓이지만 미드필더는 그렇지 않다. 보정이 없으면 미드필더의 평점이 늘 낮게 나온다. 이 숫자는 시뮬레이션을 돌려 "평균 선수가 평균 6.3~6.5"가 되도록 맞췄다.

종목별 표는 각 문서에 있다 → [야구](09-baseball-player-mode.md#경기-평점), [축구](08-player-mode.md#경기-평점), [농구](11-basketball.md#경기-평점).

### 9.4 평점이 감독 신뢰와 명성을 움직인다

**감독 신뢰** (0~100, 40에서 시작)

```
평점 7.0 이상:  +1 + (평점 − 7.0) × 3     (최대 +6)
평점 6.0 미만:  −1 − (6.0 − 평점) × 3     (최대 −6)
그 사이:        변화 없음
```

평점 7.5면 +2.5, 평점 5.5면 −2.5다. 6.0~7.0은 "무난해서 감독의 생각이 안 바뀌는" 구간이다. 짧게 뛴 경기는 따로 봐서 ±0.5만 움직인다.

**명성** (0~100)

```
오르는 양 = (평점 − 기준) × 0.8 × 희소성 × 기세 × (한도 − 지금 명성) / 한도
```

- 기준: 야구 6.5, 축구·농구 6.3. 이보다 잘한 만큼만 오른다. 못했다고 내려가지는 않는다.
- 희소성: 선발 투수 3배(나오는 경기가 적다), 축구·농구 2배, 야구 타자 1배.
- 마지막 항이 핵심이다. 리그마다 명성 한도가 있고(6부 20, 1부 100), 한도에 가까울수록 덜 오른다. **6부에서는 아무리 잘해도 명성 20을 못 넘는다.** 더 유명해지려면 윗 리그로 가야 한다.

**스카우트의 관심도** (구단마다 0~100)

나를 지켜보는 구단이 세 곳까지 있고, 구단마다 관심도가 따로 쌓인다.

```
경기마다 변화 = (평점 − 기준) × 8 × 희소성 + 입지 + 명성 ÷ 100
```

- 기준은 명성보다 0.3 낮다 (야구 6.2, 축구·농구 6.0). 평점 7.0이면 축구 선수는 +8이다.
- 입지: 그 구단에 가면 주전이면 +3.5, 주전 경쟁이면 +1.2. 평점과 상관없이 쌓이는 몫이다.
- 스카우트가 직접 보러 온 경기는 두 배로 움직인다 (30%의 확률로 다음 경기에 온다고 미리 알려 준다).

관심도가 70을 넘은 구단이 이적 기간에 제안을 보낸다. 감독 신뢰가 "지금 구단에서의 자리"라면, 스카우트의 관심도는 "다음 구단으로 가는 길"이다. 둘 다 평점에서 나오지만 따로 쌓인다.

### 9.5 세계가 한 걸음 나아간다

경기 하나가 끝날 때마다 "세계의 틱"이 한 번 돈다.

1. **모든 선수가 조금 자란다** (10절).
2. CPU 구단이 선수단을 정비한다.
3. 이적 시장: 이적 기간이고 관심도가 문턱을 넘은 스카우트가 있으면 그 구단이 제안한다.
4. 컵대회 차례가 됐으면 연다.
5. 정규시즌의 마지막 라운드였으면 시상과 승강 플레이오프로 넘어간다.

## 10. 훈련과 성장

능력치가 오르는 길은 세 가지다.

### 10.1 훈련 (포인트를 쓴다)

훈련 한 번은 **능력(CA)을 정해진 양만큼** 올린다. 어떤 훈련이든 같고, 리그에 따라 다르다: 6부 0.025, 5부 0.03, 4부 0.035, 3부 0.04, 2부 0.045, 1부 0.05. 한 번은 작지만 한 시즌에 220번쯤 할 수 있어서, 빠짐없이 하면 6부에서 +5.5, 1부에서 +11이 오른다. 아래 설명은 3부(0.04)를 예로 든다.

그러려면 능력치마다 오르는 양이 달라야 한다. 비중이 38%인 슈팅은 0.105만 올려도 능력이 0.04 오르지만(0.105 × 0.38), 비중이 7%인 체력은 0.57을 올려야 한다(0.57 × 0.07).

```
한 번에 오르는 능력치 = 리그별 훈련 효과 ÷ 그 능력치의 비중
```

> 처음에는 "훈련 한 번에 능력치 +1"이었다. 그랬더니 능력치 종류가 적은 골키퍼(골키핑 70%)가 다른 포지션보다 1.5배 빨리 컸다. 그래서 "능력이 같은 양만큼 오르게" 바꿨다.

**비용**은 지금 그 능력치의 값으로 정해진다.

```
비용 = 250,000 × e^((지금 값 − 25) × 0.0615)
```

| 능력치 값 | 25 | 40 | 50 | 60 | 70 | 85 |
|---|---|---|---|---|---|---|
| 한 번의 비용 | 25만 | 63만 | 116만 | 215만 | 397만 | 1,000만 |

여기에 리그별 배수가 곱해진다: 6부 0.5배, 5부 0.7배, 4부 1.0배, 3부 1.3배, 2부 1.6배, 1부 2.0배. 윗 리그일수록 한 번에 많이 오르지만 더 비싸다.

값이 11 오를 때마다 비용이 두 배가 된다. 그래서 윗 리그에서는 포인트가 훈련 횟수를 정한다. 능력치 70을 2부에서 올리려면 한 번에 635만 포인트가 들어, 경기마다 다섯 번을 다 채우기 어렵다. 그래서 **낮은 능력치를 올리는 것이 싸다.** 다만 낮은 능력치는 대체로 비중도 낮아서 경기에 덜 쓰인다. 무엇을 올릴지가 선택이 되는 이유다.

제한은 네 가지다.

- 경기 사이에 다섯 번 (설정에서 "추가 훈련"을 켜면 그 뒤로 1.5배, 2.25배…로 비싸지며 계속할 수 있다).
- 능력이 잠재력을 넘지 못한다. 남은 여유가 10 이하면 비용이 두 배다.
- 정해진 나이부터는 못 한다 (야구 31세, 축구 필드 29세, 골키퍼 32세, 농구 30세).
- 100번에 한 번은 "크리티컬"로 세 배 오른다.

잠재력에 닿으면 **한계 돌파 훈련**(3,000만 포인트)으로 잠재력을 1 넓힌다.

### 10.2 경기를 뛰면 저절로 큰다

세계의 틱마다 모든 선수가 조금씩 자란다.

```
성장 = 0.5 × 나이 계수 × 여유 × 구단 훈련 시설 × 출전 계수
```

- **나이 계수**: 어릴수록 크다 (22세까지 1.5, 20대 중반 1.0, 그 뒤 0.4, 30 전후로 0).
- **여유**: `(잠재력 − 능력) ÷ 잠재력`. 잠재력까지 멀수록 빨리 큰다. 능력 20에 잠재력 80이면 0.75, 능력 70에 잠재력 80이면 0.125.
- **출전 계수**: 선발 1.2, 교체 1.0, 벤치 0.6. 잘한 경기(안타·골·18점 이상 등)는 1.1배 더.
- **내 선수는 여기에 0.15를 한 번 더 곱한다.** 나머지는 훈련으로 직접 올리라는 뜻이다.

16세에 능력 20, 잠재력 80인 내 선수가 선발로 뛰면 한 경기에 `0.5 × 1.5 × 0.75 × 1.0 × 1.2 × 0.15 = 0.1`쯤 큰다. 6부의 훈련 네 번(0.025 × 4)과 같다. 경기 결과에 "이번 경기 성장: 능력 +0.10"으로 적힌다.

두 길을 따로 재 보면, 경기만 뛴 선수는 한 시즌에 능력이 3~4 오르고 여덟 시즌 뒤 3~4부 수준(능력 50~57)이 된다. 훈련을 하나도 빼먹지 않은 선수는 한 시즌에 9~12 오르고 5~6시즌에 1부에 닿는다. 실제 선수는 그 사이에 있다.

### 10.3 나이가 들면 떨어진다

시즌이 바뀔 때 나이를 한 살 먹는다.

- 30세 무렵부터: 스피드와 체력 같은 몸의 능력치가 시즌마다 0.5~1.5씩 내린다. 야구의 선구안과 제구는 오히려 조금 오른다.
- 33~35세부터: 모든 능력치가 떨어진다. 스피드와 체력은 2.5~5, 나머지는 0.5~2. 잠재력도 2씩 내린다.

📁 `Sources/TokenBaseballCore/Career/Game+CareerTraining.swift`(훈련), `Season/Game+World.swift`의 `grow`(성장), `Season/Game+Offseason.swift`(노화)

## 11. 세계는 어떻게 굴러가는가

### 11.1 리그와 일정

- 6개 리그가 위아래로 쌓여 있다. 야구와 농구는 리그마다 10팀, 축구는 20팀이다.
- 일정은 **원형 배치**로 만든다. 한 팀을 고정하고 나머지를 한 칸씩 돌려 가며 짝을 짓는다. 그러면 모든 팀이 한 라운드에 한 경기씩 하고, 정해진 라운드 뒤에 모두와 한 번씩 만난다. 이것을 홈·원정을 바꿔 반복한다.
- 내가 경기 하나를 치를 때마다 여섯 리그가 모두 한 라운드씩 나아간다.

### 11.2 팀 강도와 리그 범위

팀의 강도는 주전들의 능력 평균이다. 리그마다 강도의 범위가 정해져 있다.

| 6부 | 5부 | 4부 | 3부 | 2부 | 1부 |
|---|---|---|---|---|---|
| 20~40 | 30~50 | 40~60 | 50~70 | 60~80 | 70~92 |

범위가 10씩 겹치는 것이 승강을 재미있게 만든다. 6부 1위(40)와 5부 꼴찌(30)는 실력이 뒤집혀 있다. 승격한 팀이 곧바로 꼴찌를 하지는 않는다.

### 11.3 승강과 컵대회

정규시즌이 끝나면 순위에 따라 자동 승격·강등과 플레이오프가 정해진다. 야구와 농구는 와일드카드와 3전 2선승의 승강전, 축구는 잉글랜드 방식(위 두 팀 자동 승격, 3~6위 플레이오프, 아래 세 팀 강등)이다. 내 팀이 끼지 않은 경기는 화면 없이 바로 끝까지 치른다.

컵대회는 리그 사이사이에 끼어드는 단판 승부다. 모든 구단이 나오고 매 라운드 다시 추첨한다.

### 11.4 토큰은 어떻게 읽는가

앱은 AI 코딩 도구들이 컴퓨터에 남기는 로그 파일을 20초마다 읽는다. 응답 하나하나에 적힌 토큰 수를 더해서 훈련 포인트로 준다. 같은 응답을 두 번 세지 않게 응답마다의 고유 번호를 기억하고, 선수를 만들기 전에 쓴 토큰은 세지 않는다. 파일은 읽기만 하고 어디로도 보내지 않는다.

📁 `Sources/TokenBaseballCore/League/Schedule.swift`(일정과 순위), `Season/`(시즌 흐름, 승강, 컵대회), `Usage/`(토큰 읽기)

## 12. 직접 실험해 보기

구조를 익히는 가장 빠른 길은 숫자를 바꿔 보고 결과를 보는 것이다.

### 엔진만 돌려 보기

테스트 폴더에 "능력이 같은 두 팀을 수백 번 붙여 평균을 내는" 도구가 있다.

```sh
swift test --filter BasketballEngine     # 농구 엔진 (7초)
swift test --filter FootballEngine       # 축구 엔진
swift test --filter MatchEngine          # 야구 엔진
```

농구 테스트는 평균 득점, 성공률, 리바운드, 출전 시간을 한 줄로 찍는다. `Tests/TokenBaseballCoreTests/Basketball/BasketballEngineTests.swift`의 `BasketballSample.run(away: 60, home: 60, games: 300)`에서 숫자를 바꿔 보면 된다.

해 볼 만한 실험:

- `away: 50, home: 60`으로 바꿔 능력 10 차이의 승률을 본다.
- `BasketballMatch.swift`에서 3점슛 기본 확률 `0.24`를 `0.35`로 올리고 평균 득점이 어떻게 변하는지 본다.
- 축구의 슈팅 확률 `0.21`을 `0.30`으로 올리면 경기당 골이 몇 골이 되는지 본다.

### 숫자가 모여 있는 곳

균형에 관한 숫자는 대부분 두 파일에 모여 있다.

- `Sources/TokenBaseballCore/Balance.swift`: 리그 크기, 능력 범위, 성장, 나이, 연봉
- `Sources/TokenBaseballCore/Career/Balance+Career.swift`: 선수 모드의 훈련 비용, 감독 신뢰, 명성, 컨디션

경기 엔진 안의 확률(슈팅 21%, 땅볼 44% 같은 것)은 엔진 파일에 직접 적혀 있다.

### 화면 없이 앱 흐름 돌려 보기

```sh
swift build && TOKEN_BASEBALL_SELFTEST=/tmp/tb-selftest .build/debug/TokenBaseball
```

선수를 만들고, 훈련하고, 경기를 치르고, 모드를 바꾸고, 껐다 켜는 흐름을 화면 없이 돌려 PASS/FAIL로 찍는다.

## 13. 코드 지도

코드는 두 덩어리다.

- **`TokenBaseballCore`**: 게임의 규칙 전부. 화면이 없다. 테스트는 여기만 본다.
- **`TokenBaseball`**: 화면(SwiftUI)과 앱. Core를 불러 쓰기만 한다.

"규칙이 궁금하면 Core, 생김새가 궁금하면 앱"이다.

```
Sources/TokenBaseballCore/
  Support/SeededRNG.swift          주사위 (2절)
  Players/Player.swift             선수, 포지션, 능력치와 비중 (3절)
  Players/PlayerFactory.swift      선수 만들기
  Match/
    MatchState*.swift              야구 엔진 (5절)
    FootballMatch*.swift           축구 엔진 (6절)
    BasketballMatch*.swift         농구 엔진 (7절)
  League/                          일정, 순위, 선발 명단 짜기
  Game/
    Game.swift                     게임 상태 전체 (이 하나를 저장한다)
    Game+Match.swift               경기 시작·진행·정산 (야구)
    Game+Football.swift            같은 일 (축구)
    Game+Basketball.swift          같은 일 (농구), 농구의 출전과 평점
  Career/                          선수 모드: 출전, 평점, 훈련, 계약, 시즌 목표 (8~10절)
  Season/                          시즌 흐름, 승강, 컵대회, 오프시즌, 세계의 틱 (9, 11절)
  Usage/                           토큰 로그 읽기
  Persistence/SaveStore.swift      저장 파일
  Balance.swift                    조정할 수 있는 숫자들

Sources/TokenBaseball/
  Model/AppModel*.swift            앱 상태, 3초마다 틱을 부르는 반복문
  Views/                           화면
  Sprites/                         도트 그림
```

읽는 순서를 권한다면:

1. `SeededRNG.swift` (80줄): 주사위가 무엇인지.
2. `BasketballMatch.swift`: 엔진 하나를 처음부터 끝까지. 가장 짧다.
3. `Player.swift`의 `Attributes`: 능력치와 비중.
4. `Game+Basketball.swift`: 엔진을 게임에 어떻게 붙이는지 (경기 시작, 기록 옮기기, 평점).
5. `Game+CareerMatch.swift`의 `settleCareer`: 평점이 신뢰와 명성이 되는 곳.
6. `Game+World.swift`의 `tick`과 `grow`: 경기 뒤 세계가 움직이는 곳.

그다음에 야구와 축구 엔진을 보면 "같은 원리의 다른 모양"으로 읽힌다.
